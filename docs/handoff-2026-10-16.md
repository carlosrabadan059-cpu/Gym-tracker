## Cómo se cambia la imagen de un ejercicio

Carlos manda la imagen y dice el número. **Antes de nada, comprobar que el
nombre de la imagen coincide con el de `exercise_catalog` para ese id**: las
imágenes generadas traen números que no siempre cuadran (pasó con #70/#71 y
con #77). Si no coincide, preguntar.

1. Copiar a `public/exercises/v2_<categoría>_<id>_<sufijo>.png`, con nombre
   nuevo para evitar la caché.
2. Añadirla a `LOCAL_IMAGES` en `src/views/trainer/TrainerLibraryView.jsx`.
3. Commit y push.
4. `update exercise_catalog set image_url=…` y lo mismo en `exercises` con ese
   `catalog_id` (solo `image_url`).
5. Desplegar en iPhone **y** Watch (ver abajo).

Si la imagen no llega a `.../scratchpad/../images/`, mirar en
`~/Downloads/` (Carlos la descarga ahí).

## Desplegar en nativo: siempre los dos dispositivos

Regla de Carlos tras perder la app del Watch el 14-10: cada despliegue va al
iPhone y al Watch, sin preguntar, y se verifica que los dos la tienen
instalada.

```bash
npm run build && git checkout public/version.json && npx cap sync ios
cd ios/App && xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'id=<iPhone>' -allowProvisioningUpdates build
P=~/Library/Developer/Xcode/DerivedData/App-*/Build/Products/Debug-iphoneos
xcrun devicectl device install app --device <iPhone> $P/App.app
xcrun devicectl device install app --device <Watch> "$P/App.app/Watch/RutinexWatch Watch App.app"
xcrun devicectl device info apps --device <Watch> | grep -i rutinex   # comprobar
```

Los ids están en `xcrun devicectl list devices`. Si un dispositivo sale
`unavailable` o hay timeout, pedir a Carlos que lo desbloquee y reintentar.
No dar el despliegue por hecho.

## Web en Dokploy (2026-10-19)

La web también se sirve en https://rutinex.rabadanhouse.space, desde Dokploy
(proyecto "Rutinex", app `rutinex-web`), con el `Dockerfile` y `nginx.conf`
del repo (commit `2b1e1e2`). Vercel sigue activo y sin tocar.

- Las 6 `VITE_*` van como **build args** de la app en Dokploy, no como env:
  Vite las mete en el bundle al compilar. Sin ellas el build falla a propósito
  (`test -n` en el Dockerfile) en vez de dar una página en blanco.
- El tráfico entra por el túnel de Cloudflare (`Tunel_DEBIAN-SUPA…`); la IP del
  servidor no responde directamente. Un subdominio nuevo se añade como Public
  Hostname del túnel.

  (`Dokploy-2026-09-14-rb53sr`), igual que Vinoteca. Un push despliega a la vez
  en Vercel y en Dokploy.
